## Detailed Issue Records

### Q-007: `moreFeature` renders nothing

- **The Ambiguity:** Every `knowledgebase.json` (all 11 country folders) and `src/data/in/hello.json` contain a top-level `moreFeature` object, but no component is registered under that key. `src/pages/[[...slug]].js` logs `Component "moreFeature" is undefined` and skips it.
- **Affected Code & Paths:**
    - `src/data/global/knowledgebase.json`
    - `src/components/PageRenderer/PageRenderer.js:PageRenderer`
- **Current Evidence:**
    - `node scripts/check-page-data.mjs` reports these keys when `knownUnregisteredKeys` is emptied.
- **Potential Risk:** Content someone wrote has never appeared on the site.
- **What Resolves This:** The content owner says whether the section should show. Then either map it to an existing component (`MoreServicesComp` is a plausible match, unverified) or delete the key, and remove it from `knownUnregisteredKeys`.

### Q-005: Two sources of response headers

- **The Ambiguity:** `next.config.mjs:headers` sets HSTS, `X-Frame-Options`, COOP and CORP. `public/_headers` sets a different, stricter set, including `Content-Security-Policy: default-src 'self'; script-src 'self'`.
- **Affected Code & Paths:** `next.config.mjs`, `public/_headers`
- **Potential Risk:** If the host applies `_headers`, third-party scripts (GTM, Clarity, Hello chat, OTP widget) are blocked. If it doesn't, the file misleads readers.
- **What Resolves This:** Confirm the host, then keep one header source.

## Known Technical Limitations & Verification Gaps

- **No backend or credentials during preparation:** No `.env` was available. Pricing, sign-up, chat widget and OTP widget calls were not exercised. Browser consoles show connection errors and `/undefined` script loads from the unset variables, both before and after the cleanup. Mitigation: verification compared server-rendered HTML for 360 URLs and checked the build. Interactive sign-up and pricing calculators were not clicked through. <!-- verify:ignore -->
- **Hosting layer not available:** `public/_redirects` and `public/_headers` are not applied by `npm start`, so redirect behaviour was not verified.
- **No automated tests:** The repo has no test runner. `scripts/check-page-data.mjs` is the only automated check besides the build.
